# Implementation Plan

## Overview

Build "Gasmeter Downloader" from scratch as a Windows desktop application (PyQt6 + QtCharts) that automatically downloads daily gas-meter logfiles from an AI-on-the-Edge device, stores meter values in a local SQLite database (the single source of truth), interpolates missing days, supports manual correction and restore, archives logfiles forever, visualizes consumption statistics (with kWh/m³ switching, year-over-year comparison, trendlines and projections), follows the native Windows light/dark theme, is fully bilingual (English/German), and self-updates exclusively through the shared `github_updater` package (Python_Units) fed by GitHub Releases.

The repository is currently empty (only `README.md`, `LICENSE`, `.gitignore`, and `test/logfiles/` with two sample files). All application code is new. The architecture follows Clean Architecture principles: pure domain logic in the inner layer, application use-cases with protocol-based ports in the middle, and framework/DB/HTTP/filesystem/GUI adapters in the outer layer. The implementation mirrors conventions proven in the reference project `MusicSceneReleaser` (package `app/`, `_version.py` generated by CI, GitHub Actions lint/test/build/release pipeline, PyInstaller one-file `.exe`, `github-updater @ git+https://github.com/reserve85/Python_Units.git`).

### Key decisions (confirmed with the owner)

1. **Updater**: `github_updater.UpdateService` from `https://github.com/reserve85/Python_Units` is used *only* for the application self-update. It is NOT used for meter data.
2. **Distribution**: PyInstaller one-file, windowed `.exe`; built on `windows-latest` for git tags `v*`; released as GitHub Release (`.exe` + `.zip`) via `softprops/action-gh-release@v2`. Version string written to `app/_version.py` at build time.
3. **Update source**: GitHub Releases of `reserve85/Gasmeter-Downloader` (owner `reserve85`, repo `Gasmeter-Downloader`, app_name `GasmeterDownloader`).
4. **Charts**: QtCharts via `PyQt6.QtCharts`.
5. **No `confirmed` flag**: a daily record has three values instead — `import_value`, `interpolated_value`, `adjusted_value` — plus a `source` (`logfile` | `interpolated` | `manual`).
6. **Interpolation**: fill *any* gap that has both a left and a right boundary (no maximum gap length).
7. **Language**: English and German; selection stored in the app config (`auto` = detect from Windows locale, fallback English); all user-visible strings go through the i18n module.
8. **Units**: database stores volumes in **m³**. kWh is a derived display unit computed per calendar day from the gas-parameter interval valid on that day: `kWh = m³ * calorific_value * z_value`. All calculations inside the domain use `decimal.Decimal`; SQLite stores REAL; display formatting is locale-aware (de: `3.116,4` | en: `3,116.4`).
9. **Value extraction** (`test/logfiles` verified + Delphi reference): a daily logfile's meter value is *the last successful reading* in the file:
   - **CSV** `data_YYYY-MM-DD.csv` (current format, headerless, 15–16 comma-separated columns, trailing sensor columns vary): a row is successful when it contains the error text `no error`; the meter value is column index **3** (`timestamp,channel,raw,value,prev,rate,?,error,…`). The last such row in the file wins. Error rows (e.g. `Neg. Rate`) have an empty value column and are skipped.
   - **TXT** `log_YYYY-MM-DD.txt` (legacy format): scan for lines matching `PostProcessing - Raw: … Value: <number> Error: no error`; the value is the text between `Value: ` and ` Error:`. The last match wins. Files can be large (~1.2 MB) — parse streaming, line by line.
   - The device file server lists the day in the file name (`data_YYYY-MM-DD.csv`), so the reading date comes from the file name; timestamps inside rows are informational only.
10. **`Python_Units` / `python-units`**: the PyPI `python-units` library is a unit *conversion* library and is **not** used. Measurement-unit logic is implemented in the domain (`conversion.py`).
11. **Three stored values & change discipline**: every day stores `import_value`, `interpolated_value`, and `modified_value` (i.e. `adjusted_value`; displayed as "Modified"). The table shows **all three** values plus `source`. **Only the Modified value can be changed by the user.** Trust/priority hierarchy: **modified > imported > interpolated** — the effective value used everywhere is `modified_value`. Rules: manual edits never overwrite `import_value`; importing a logfile into a day that already has a manual modification only backfills `import_value` (the `modified_value` and `source=manual` stay intact); interpolation only ever fills/refreshes rows with no entry or `source=interpolated`.
12. **Global date-range filter**: a single from/to + presets filter applies to **the table and all charts simultaneously**.
13. **Instant reactivity ("AJAX‑like")**: a `DashboardController` recomputes the `Dashboard` and refreshes the table + every chart card on any change (filter, unit, aggregation, YoY, trend, or after a completed import) — Qt signals propagate immediately. Network-heavy operations (download/import/update) still run on a worker thread and then trigger one refresh. The dataset is small (one row per day), so refresh is effectively instantaneous.
14. **Settings source of truth & app defaults**: all runtime settings live in **`config/app_config.yaml`** (yes, a config file is used — it is the registry for user changes). Applications defaults (applied only on first run or when a key is missing):
    - Device IP: **`192.168.10.65`**
    - Gas parameters for the initial interval covering "the foreseeable past" (default `valid_from` = earliest imported date; the preset interval value is `valid_from` defaulted to the DB start, `valid_to` unbounded/`NULL`): **Calorific value `11.342` kWh/m³**, **Z-value `0.9589`**
    - Download window: **`max_download_days = 30`** (replaces the earlier "last 20 days"; yesterday always included when missing, today always skipped)
    - Folders default **in the `.exe` root** (or repo root in dev): `downloads/`, `archive/`, DB `gasmeter.db`
    - Language `auto`, default unit `m³`, window geometry defaults
15. **Config decision**: a YAML config file is kept (`config/app_config.yaml`) — it is the single, inspectable place where folder/IP/z/calorific/max-days/language/unit/token are configured and every change is logged. On first run it is created beside the app with the defaults above; the Settings dialog edits it; `YamlAppSettings` merges any missing keys with defaults on load. Gas parameters additionally live in the SQLite `gas_parameters` table as dated intervals (single source of truth for *what applies on a given day*).
16. **Logging — in-memory only, no files**: the **only** log in the app is the in-GUI **UI Log panel** — a pure in-memory user feed (imports, downloads, interpolations, warnings, errors) that shows the user what happened during the session. It is **never saved to any file** (`GasmeterDownloader.log` and rotation are **removed — spec §10's "logfile stored locally / log rotation" is overridden by owner decision**), not restored on restart, and there is no persistent log of any kind. All `EventLogger` events go exclusively to the live UI panel.

> **Spec deviation (owner):** original spec §10 required a locally-stored rotating logfile. Per owner clarification (2026-08-29), **no file logging whatsoever** — only the in-memory UI log panel.
### Statistics & Visualization design (best-practice review)

`ChartsTab` is a scrollable dashboard of self-contained chart cards, driven by a single `GetDashboardUseCase` query (all aggregations precomputed so switching is instant):

1. **KPI row (top)** — the most informative numbers at a glance: total consumption in the selected range/unit, average per day, maximum day (date + value), number of interpolated days in range, latest meter value. Small stat cards with localized labels.
2. **Meter reading card (cumulative line, always increasing)** — XY line of `adjusted_value` over time in the selected unit; points for each day; **interpolated spans are drawn dashed/fainter** so users see data quality; tooltips show date, value, source.
3. **Usage card (bar chart)** — consumption per **day**, with an inline aggregation switch **Daily / Weekly / Monthly** applied instantly from precomputed buckets. With the trend toggle on, a dashed OLS trendline plus forward projection overlay the daily view.
4. **Monthly block diagram card** — column chart aggregated per calendar month (independent of the usage-card switch). With "previous year" enabled it shows **two bars per month (current vs previous year)** as the year-over-year comparison; otherwise single bars. This is the request "block diagram for usage per month".

UX rules applied: one chart = one message; consistent unit across all cards via the global kWh/m³ switch; empty data → friendly placeholder instead of a blank chart; tooltips everywhere; from/to pickers plus presets (last 7/30 days, this/last month, this year, last 12 months, all time); theme-aware colors; source coloring only where it adds insight (meter card). All charts consume **`adjusted_value`** only.

### Global date-range filter & instant reactivity

- **Single filter source of truth**: the `MainWindow` toolbar hosts a global filter widget — from/to `QDateEdit`, presets (last 7/30 days, this/last month, this year, last 12 months, all time) — stored in the `DashboardController`. The **table and every chart card** consume the same `QueryRequest` interval, so a change updates all views consistently.
- **`DashboardController` (QObject, presentation layer)**: owns the current view state (`QueryRequest`) and the `GetDashboardUseCase`. API: `set_date_range(start,end)`, `set_unit(unit)`, `set_aggregation(agg)`, `set_include_previous_year(bool)`, `set_trendline(bool)`, `refresh()`. Every setter updates state and calls `refresh()`, which runs the local, fast query and emits `dashboard_changed(Dashboard)`. Consumers (table model, KPI cards, chart cards) are slot-connected and repaint immediately — "AJAX-like" behavior.
- **Mutating actions**: a completed sync/import, manual edit, restore, or settings change calls `controller.refresh()` afterwards, so all views update at once. Network/worker paths (download, archive import, update check) run on `SyncWorker`/task threads and only emit a completion signal; the controller refresh happens on the UI thread.
- **Granularity**: aggregation, unit, YoY and trend toggles only re-query locally (no network, no disk writes) — instant.
- **Logging**: each refresh logs a `GUI`/`QUERY` event via `EventLogger` (chart-rendering events are logged as required).

## Types

All type definitions live in `app/domain/entities.py` (domain value objects/enums) and `app/application/` (request/response models). Numeric values use `decimal.Decimal` in domain code; SQLite stores REAL.

### Enums

```python
# app/domain/entities.py
from enum import Enum

class Source(str, Enum):
    LOGFILE       = "logfile"        # value came from a logfile
    INTERPOLATED  = "interpolated"   # value filled by linear interpolation
    MANUAL        = "manual"         # value set/corrected by the user

class LogLevel(str, Enum):
    DEBUG = "DEBUG"; INFO = "INFO"; WARNING = "WARNING"
    ERROR = "ERROR"; CRITICAL = "CRITICAL"

class Aggregation(str, Enum):
    DAILY = "daily"; WEEKLY = "weekly"; MONTHLY = "monthly"

class ViewUnit(str, Enum):
    M3  = "m³"
    KWH = "kWh"

class Language(str, Enum):
    AUTO = "auto"; EN = "en"; DE = "de"

class LogCategory(str, Enum):
    STARTUP; SHUTDOWN; DOWNLOAD; PARSE; IMPORT; IGNORE; ARCHIVE
    INTERPOLATE; EDIT; RESTORE; SETTINGS; GAS_PARAMS; GUI
    UPDATE; DB; THEME; ERROR
```

### Domain entities (value objects; `frozen=True, slots=True`)

```python
@dataclass(frozen=True, slots=True)
class DayReading:
    day: date
    import_value: Decimal | None        # raw meter value from logfile (never overwritten)
    interpolated_value: Decimal | None  # last computed interpolation (restore target w/o import)
    adjusted_value: Decimal             # = modified value; the effective value used everywhere (modified > imported > interpolated)
    source: Source
    updated_at: datetime

@dataclass(frozen=True, slots=True)
class GasParameterInterval:
    valid_from: date                    # inclusive
    valid_to: date                      # inclusive
    calorific_value: Decimal            # kWh/m³ (Hs)
    z_value: Decimal                    # Z-number (compression factor)
```

### Domain service results (pure data)

```python
@dataclass(frozen=True, slots=True)
class ParseResult:
    day: date
    value: Decimal | None               # extracted last successful reading (None = unusable)
    rows_read: int
    candidates: int                     # successful rows considered
    note: str                           # summary for logging

@dataclass(frozen=True, slots=True)
class GapFill:                          # one interpolated day
    day: date
    value: Decimal

@dataclass(frozen=True, slots=True)
class ImportOutcome:
    day: date; status: str              # imported|already-present|no-value|skipped-today|outside-window
    value: Decimal | None; note: str

@dataclass(frozen=True, slots=True)
class SyncResult:
    downloaded: list[date]
    imported: list[ImportOutcome]
    missing_on_device: list[date]       # HTTP 404 -> warning
    failed: list[tuple[date, str]]      # download/parse/archive errors
    archived: list[Path]

@dataclass(frozen=True, slots=True)
class ConsumptionPoint:
    day: date
    volume_m3: Decimal                  # Δ adjusted_value for the bucket
    energy_kwh: Decimal

@dataclass(frozen=True, slots=True)
class DataSeries:
    name: str
    unit: ViewUnit
    points: list[ConsumptionPoint]

@dataclass(frozen=True, slots=True)
class Trendline:
    slope: Decimal
    intercept: Decimal
    r2: Decimal
    series: DataSeries                  # fitted line over the selected range

@dataclass(frozen=True, slots=True)
class MeterPoint:
    day: date
    adjusted_value: Decimal             # meter progression from DB (m³)
    display_value: Decimal              # converted to current view unit

@dataclass(frozen=True, slots=True)
class KpiSummary:
    total_energy: Decimal                    # total consumption in selected unit over range
    average_per_day: Decimal
    max_day: ConsumptionPoint | None         # highest single bucket + its date
    interpolated_days_in_range: int          # days with source=INTERPOLATED in range
    latest_meter_value: Decimal | None       # last adjusted value in range (selected unit)

@dataclass(frozen=True, slots=True)
class Dashboard:
    unit: ViewUnit
    meter_series: list[MeterPoint]                               # cumulative meter line (always increasing)
    consumption: dict[Aggregation, list[ConsumptionPoint]]       # daily/weekly/monthly buckets (selected unit)
    previous_year: dict[Aggregation, list[ConsumptionPoint]] | None  # YoY overlay per aggregation
    trendline: Trendline | None                                  # OLS on daily usage + forward projection
    kpi: KpiSummary
    table_rows: list[tuple[date, Decimal | None, Decimal | None, Decimal, Source]]  # date, import, interpolated, modified, source
```
### Application ports (protocols, `app/application/ports.py`)

```python
class Clock(Protocol):                def today(self) -> date: ...
class EventLogger(Protocol):          def log(self, category: LogCategory, level: LogLevel, message: str) -> None: ...

class MeterRepository(Protocol):
    def get_reading(self, day: date) -> DayReading | None
    def get_readings(self, start: date | None, end: date | None) -> list[DayReading]
    def all_days_with_import(self) -> set[date]
    def save_import(self, day: date, value: Decimal) -> None            # import+adjusted set, source=LOGFILE
    def save_interpolated(self, day: date, value: Decimal) -> None      # interpolated+adjusted set, source=INTERPOLATED
    def save_manual(self, day: date, value: Decimal) -> None            # adjusted set only, source=MANUAL
    def restore_to_original(self, day: date) -> None                    # adjusted <- import or interpolated
    def latest_reading_day(self) -> date | None

class GasParameterRepository(Protocol):
    def all_intervals(self) -> list[GasParameterInterval]
    def upsert_interval(self, interval: GasParameterInterval) -> None
    def delete_interval(self, valid_from: date, valid_to: date) -> None
    def parameter_for(self, day: date) -> GasParameterInterval | None

class LogfileSource(Protocol):                                          # AI-on-the-Edge device
    def available_days(self) -> list[date]                              # parsed from HTML directory listing
    def download(self, day: date, target_dir: Path) -> Path | None     # None = 404/not available

class LogfileParser(Protocol):
    def parse(self, path: Path) -> ParseResult

class LogfileArchiver(Protocol):
    def archive(self, path: Path) -> Path | None                       # move, never delete; None if already archived
    def is_archived(self, path: Path) -> bool

class AppSettings(Protocol):                                            # YAML-backed app settings
    def get(self, key: str, default: Any = None) -> Any
    def set(self, key: str, value: Any) -> None
    def to_dict(self) -> dict

class UpdatePort(Protocol):                                             # wraps github_updater.UpdateService
    def check(self, token: str) -> dict                                 # {"has_update", "latest_version", ...}
    def download(self, url: str, token: str, progress) -> str
    def apply(self, path: str) -> bool
    def restart(self) -> None
```

```python
class ParamsIntervalRequest:
    valid_from: date; valid_to: date
    calorific_value: Decimal; z_value: Decimal
```

```python
def consumption_series(readings: list[DayReading], start: date, end: date,
                       unit: ViewUnit, intervals: list[GasParameterInterval]) -> list[ConsumptionPoint]:
    """Daily Δ adjusted_value, converted per day to the requested unit.
    The first day of the range consumes the reading of the preceding day; if that
    predecessor is missing the day is omitted and a WARNING is logged. Negative
    differences (meter resets / manual corrections) are shown as-is (DEBUG log)."""

    """total energy, average/day, max day, interpolated-day count, latest meter value."""

def linear_regression(points: list[ConsumptionPoint]) -> tuple[Decimal, Decimal, Decimal]:
```

```python
# app/application/use_cases/sync.py
class SyncMissingLogfilesUseCase:
    def __init__(self, repo, params_repo, source, parser, archiver,
                 settings, logger, clock): ...
    def run(self) -> SyncResult: ...     # uses settings['device.max_download_days'] (default 30),
                                         # list device then _download_one/_import_one per missing day,
                                         # interpolate afterwards
    def _missing_days(self) -> list[date]:
        """Window = settings `max_download_days` (default 30) up to yesterday (excl.
        today). Days already having import_value are skipped. Logs 'ignored today'."""
    def _import_one(self, path: Path) -> ImportOutcome:
        """Parse file, store import_value for its day. If the day already has a
        manual modification (source=manual), only backfill import_value and leave
        modified_value + source untouched (modified > imported). If already has
        import_value from logfile, skip (already-present). Then archive the file."""
    def _download_one(self, day: date) -> Path | None:
        """HTTP GET for the day; None on 404/timeout; saves into downloads/."""

    def _import_one(self, path: Path) -> ImportOutcome: ...
    # Rule: files already located inside the archive folder are NOT moved again;
```
